# Portable manifests

Plain Kubernetes YAML that applies to any cluster. No VIPs, no private
registry, no cluster-specific issuer — unlike [`../`](../README.md), which is
one real cluster's configuration and is kept concrete on purpose.

```bash
# 1. Point at your own Postgres. The manifests do not run one: a database is a
#    stateful service with backup and upgrade concerns that belong to whoever
#    operates it.
kubectl create namespace fastllm
kubectl -n fastllm create secret generic fastllm-database \
  --from-literal=uri='postgres://user:pass@host:5432/fastllm'

# 2. Generate the two secrets. Keep them: rotating the encryption key needs
#    `fastllm-proxy reencrypt-backends` first, not just a restart, and losing
#    it loses every upstream credential in that database.
kubectl -n fastllm create secret generic fastllm-secrets \
  --from-literal=proxy-token="pt-$(openssl rand -hex 24)" \
  --from-literal=encryption-key="$(openssl rand -hex 32)"

# 3. Apply.
kubectl apply -k deploy/kubernetes/base/

# 4. Give yourself a login. There is no default password to forget to change.
kubectl -n fastllm exec deploy/fastllm-control -- \
  fastllm-proxy set-password --name you --password 'change-me'
```

The secrets are not generated by the kustomization on purpose: that would put
a proxy token and a non-regenerable encryption key in git.

## What you get

| | |
|---|---|
| `fastllm-control` | 1 replica. Database, admin API, management UI, `/snapshot`. ClusterIP on `:4001` |
| `fastllm-proxy` | 2 replicas, spread across nodes. The gateway. ClusterIP on `:4000` |
| `fastllm-proxy-config` | The `fastllm:` tuning block. Reloaded without a rollout |
| PodDisruptionBudget | `minAvailable: 1`, so a rolling node drain cannot take the whole gateway |

Reach the UI without exposing it:

```bash
kubectl -n fastllm port-forward svc/fastllm-control 4001:4001
```

## Overlays

```bash
kubectl apply -k deploy/kubernetes/overlays/tls/            # admin listener on TLS
kubectl apply -k deploy/kubernetes/overlays/loadbalancer/   # gateway on an external address
```

**Run the TLS overlay wherever a backend has a real credential.** `/snapshot`
returns *decrypted* upstream credentials to anything holding the proxy token,
so plain HTTP means every provider key you hold crosses the cluster network in
the clear. It needs cert-manager and a `ClusterIssuer` — rename it in
`overlays/tls/certificate.yaml` if yours is not called `cluster-ca`.

The `loadbalancer` overlay moves only the **gateway** Service. The admin
Service stays ClusterIP, which is the point of having two.

## Changing the image

One line in `base/kustomization.yaml`, for both planes at once:

```yaml
images:
  - name: ghcr.io/azrtydxb/fastllm-proxy
    newTag: v0.2.0
```

Never pin them apart. They share a database schema, and a proxy older than its
control plane reads a snapshot with fields it does not understand.
